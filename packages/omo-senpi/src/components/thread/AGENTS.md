# thread component

Cross-session thread tools: fourteen agent-callable tools — ten addressing PEER sessions (terminal, desktop, or tool-created) on every `senpi --mode rpc --multi-session` socket host the agent dir holds (the legacy endpoint plus each per-thread `i-*` / per-parent `p-*` shard), and four relay tools through which a session reports to the external chat thread it is bound to and a connector drains and answers it (outbox, reply tokens). Binding is not a session tool: the always-on gateway (as its own principal) and `omo thread bind|unbind|rebind|bindings` drive the relay SDK; the removed tool names answer with senpi removed-tool hints. The host, its ensure/handshake, and the lifecycle supervisor live in senpi (`packages/coding-agent/src/modes/rpc/`); this directory owns the tool contracts, addressing, the address book, the transcript reader, durable receipts, prompt routing, and the eval-only tool metadata (`THREAD_TOOL_EXPOSURE = "eval"`, like bash). Assembly: `tools.ts` (`registerThreadTools`) builds the tools over a `ThreadHost` port and the gateway store; `component.ts` (`createThreadComponent`) registers them unconditionally (no launch-flag gate; listed right after `task`), constructing the socket client from `live-surface.ts` unless a test injects a host. When no endpoint answers, calls fail as data `host_unavailable` — except `thread_send`/`thread_handoff`, for which nothing live IS the offline case: `queued_offline`. `index.ts` re-exports every module.

## The fourteen tools

All fourteen return `{ kind: "ok", ... }` or `{ kind: "error", error: ThreadToolFailure }` — errors are data, never exceptions. Every input that addresses a session uses `thread`, and every result, error `details`, and candidate row carries `thread` back, the exact string the verbs take back (#14044, pinned by `thread-field.test.ts`); routing ids, sockets, session paths, and endpoint internals stay in the address book.

- Peer tools: `thread_create` `{ thread?, device?, alias?, name?, cwd?, fork_from?, skills?, worktree?, idempotency_key? }` (open-or-create across devices; `alias_taken`; without an account the alias becomes the local `name` with `alias_scope: "local"` + `alias_unavailable: "sign_in" | "no_registry" | "no_remote"`, #13104; no auto-suffix anywhere); `thread_list` `{ all_scope? }` (merges the account's other devices with `device`/`resumable`/alias rows; `remote_unavailable` / `devices_unavailable` / `aliases_unavailable` metadata, #13923); `thread_read` `{ thread, cursor?, max_bytes?, wait_ms? (<= 600000, #13417), all_scope? }` (bounded, cursor-paged; `cursor_stale` on a revision move; `wait_ms` waits for a running thread to leave its running states via `SessionControl.waitSettled` — one body over the leg's watch, no polling); `thread_send` -> `steered`/`started` (with `turn_id`)/`queued`/`queued_offline` (with `queue_position`) plus `delivery_id` + `effective_mode` on both legs (#13006); `thread_interrupt` (idle -> `interrupted: false`); `thread_close` (ONE ladder: attached `unload_session {force, interrupt, children:"detach"}`, else attached `close_session` + one `get_state` probe; `foreign_live_owner`; cross-device via the device service; no live owner -> `closed: false`, stays resumable); `thread_handoff` `{ thread, match?, message, delivery?, ... }` (the only fuzzy tool, `match: "fuzzy"`); `thread_rename` (`name`/`alias` at least one; `alias_taken`; empty trim -> `invalid_arguments`, case-insensitive collision -> `name_conflict`); `thread_set_model` (provider/id -> exact id -> case-insensitive fragment ladder over the target's `getAvailableModels` catalog; `model_not_found` up to 20 `available` / `model_ambiguous` up to 10 `candidates`); `thread_set_reasoning` (`level: off|minimal|low|medium|high|xhigh|max`, `scope: session|turn`; `thinking_level_unsupported` with `supported`).
- Relay tools (store-only; bindings are connector-neutral, nothing here talks to a chat platform) and the SDK relay ops (`bind`/`unbind`/`rebind`/`bindings` — gateway/CLI only, never session tools; at most one `active` binding per `(platform, account_id, chat_id, thread_id)`, `binding_conflict` with the holder, `expected_revision` CAS (`stale_revision`), `rebind` never extends `expires_at`, queued old-revision deliveries refused `binding_closed`, never moved): `thread_report` (only an explicit report writes an outbox row, only by the binding's own session (`scope_denied`), only when active/outbound/subscribed; `kind: milestone|report|question|completion`; without `binding_id` = the ORIGINATING binding — the binding of the messages the session's current answer is for; two bound threads in one answer, or a bound message with a `user` message while another outbound binding exists, refuse `invalid_arguments`; `question` needs `request_id` and returns a reply token; `completion` only arms (`cursor: null`), written once at settle); `thread_outbox` `{ binding_id, after_cursor?, limit? (100, max 500) }` (without `after_cursor` continues after `acked_cursor`; cursors from one store-wide AUTOINCREMENT — a binding sees gaps; compare cursors, never count; acked rows kept 30 d after ack, unacked as long as the binding + 30 d; a row's `answer_state` is `in_flight` while a `thread_answer` claim hands over, `delivered` once taken); `thread_outbox_ack` (idempotent + monotonic; `cursor_invalid` past the newest row or on another binding's row; the first milestone `provider_message_id` becomes `progress_message_id`, carried as `edit_message_id`); `thread_answer` `{ binding_id, reply_token, answer }` (the HMAC reply token; `binding_mismatch` leaves the question pending; an answered question `already_answered`; a moved binding or changed incarnation `stale_token`; the answer becomes an `extension_ui_response { id, uiRequestId, value, answers, comment }` shaped per the recorded request kind, the text as `value` for a host dialog and `comment` for a `question`; a hand-off with no reply releases the claim and answers `host_unavailable`; `answer_in_progress` for <=120 s, then take-over). Full binding invariants, outbox contract, completion arms, claimant liveness, and the connector contract (`omo thread` CLI / `sdk.ts`, principals `session:<id>`/`cli:<uid>`/`binding:<id>`; a connector drives ONLY `outbox`+`ack`+`answer`+`inbound`): [`gateway/AGENTS.md`](gateway/AGENTS.md). Endpoints: `rpc_host` (multi-session host — legacy `rpc.sock`, `p-*` task host, `i-*` desktop thread host; every per-session command goes to the host socket; accepts every control; a host session's control endpoint registers on a host that binds nothing — the host socket IS the endpoint) and `tui` (exactly one session behind a POSIX `<agentDir>/rpc/tui/t-<16hex>.sock` + 0600 `<socket>.secret` sent before every request; answers the read-mostly `TUI_ENDPOINT_COMMANDS` plus whatever its `get_protocol_info` advertises — a senpi with terminal session controls adds the model/reasoning/interrupt set; `prompt`, `steer`, `follow_up`, `open_session`, `release_session` are NEVER sent to a terminal; anything unadvertised is refused `unsupported` before a connection opens; never joined to a host) — either kind receives messages the same way: the sender writes the gateway row and calls `wake`, and the receiver's own drain admits it through `pi.session.admitExternalMessage`.

## Delivery table

The receiver decides with `gateway/decision.ts` (`decideDelivery`), from the target's phase when its drain runs; the sender reads the outcome from the row, never from the `wake` reply:

| Target state | `auto` | `steer` (needs `expected_turn_id`) | `follow_up` |
| --- | --- | --- | --- |
| `idle` | admit followUp -> `started` | refuse `not_steerable` | admit followUp -> `started` |
| `mid_turn` | epoch reported: admit steer, expected turn = the running one -> `steered`; no epoch: admit followUp -> `queued` | epoch matches: admit steer -> `steered`; else refuse `turn_conflict` | admit followUp -> `queued` |
| `waiting_question` | admit followUp -> `queued` | refuse `not_steerable` | admit followUp -> `queued` |
| `compacting` | admit followUp -> `queued` | refuse `not_steerable` | admit followUp -> `queued` |
| `offline` | `queued_offline` | refuse `turn_conflict` | `queued_offline` |

`auto` never fails on a turn that ends before its steer lands: it takes the lane the target has then. A same-device drain decides at admission against the live phase. A cross-device send (`remote/relay-transport.ts`) decides from one `get_state` probe, and when the receiver answers `turn_conflict` (the probed turn ended) or `held_draft` it re-sends the record as followUp, so the result names `effective_mode: "follow_up"` (started when the target is idle, queued behind a turn that began since).

senpi's admission may still answer `held_draft` (the user is composing, or a submission has not reached the runtime): nothing is enqueued, the row stays claimable and the next wake retries, and the drain shows `queuedNotice` once. `already_admitted` settles a replayed claim without a second entry. A question answer never travels as a delivery: it goes through `thread_answer`.

## Budgets, addressing, host lifecycle, receipts

Budgets (none is a setting; `gateway/constants.ts`, `component.ts`): settle wait 250 ms (`COMPLETION_SETTLE_WAIT_MS`); write-lock wait <= 30 s total then `gateway_lock_wait_exceeded` (the drain, a completion write, and an answer release re-arm one retry after the busy timeout, off the worker queue); no hop limit (every row records its `hop`; the 7 d causal root is bookkeeping only, nothing refused); fanout 16 sessions per sender turn (`overloaded` `fanout`); sender -> target burst 8, one token per 5 s (`pair_rate`); target backlog 128 messages / 1 MiB (`queue_full`); delivery 1 MiB through the engine, 32 KiB tool message, 32 KiB relay text (`message_too_large`); queued delivery TTL 24 h or the binding's expiry; receipts 30 d; delivered/refused rows 30 d after their last change (open deliveries never pruned); retention sweep <= 256 rows per table, hourly, inside write transactions; `tui` request 1.5 s, host listing 10 s per endpoint, enumeration reused 5 s. Self-send is `loop_detected` (`self_send`); a caller-chosen causal root is refused `forged_root`; a chain back to an earlier session is delivered.

Addressing: an exact durable-id match wins immediately (under default scope an id hit outside the caller's workspace is `scope_denied`, never `not_found`); then NFKC-normalized name match over the visible entries (two or more = `ambiguous_target` with up to ten candidates). Scope = same canonical git work tree (linked worktrees count separately), realpath equality outside git; `all_scope: true` widens to every entry the daemon knows; a scoped call with no caller workspace root is `caller_context_missing`. Self-targeting is explicit only (`"self"`, the caller's durable id, the caller's exact name) — fuzzy resolution filters the caller out BEFORE scoring; `UNKNOWN_CALLER` (host passed no context) is an absent identity: `"self"` always answers `caller_context_missing`, and the fallback is a compatibility path for older hosts. Fuzzy (`thread_handoff` only): trigram Dice over name (1.0), preview (0.85), workspace basename (0.70); a leader is accepted only at score >= 0.72 with a >= 0.08 margin — a cwd-basename match tops out at 0.70 and can never auto-accept alone. Fuzzy first runs the exact ladder over every row (ended remote rows included) and takes its hit unless it is the caller; the ranked set carries the shared 500-candidate safety cap.

Host lifecycle (senpi side): `ensureHost()` starts a socket host on demand (one per endpoint), probes the occupier's version/capabilities (`multi_session`, `extension_events`), and REPLACES it on mismatch; every ensured host gets the pinned installation-wide capability profile. The supervisor byte-proxies the public socket: `transient` cold start (default) idle-exits after 15 min with zero attached connections and zero active turns (`persistent` never; env `SENPI_RPC_HOST_COLD_START`, `SENPI_RPC_HOST_IDLE_EXIT_MS`); orphan-proofing is kernel-level (inherited fd-3 pipe — the kernel closes it when the supervisor dies for ANY reason; Windows falls back to untested ~2000 ms ppid polling); session lifecycle and agent events broadcast to ALL session clients, correlated responses to the requester only; a session killed before its FIRST turn gets a NEW durable id on reopen (the engine never flushes a zero-turn session). Receipts (every tool but the two sends) are at-least-once around their side effect, replaying the stored result mapped to the current shape; exactly-once is deliberately NOT claimed — a crash between native accept and receipt commit, and a side effect that THROWS inside `execute()`, both surface honestly as `idempotency_uncertain` (the prepared receipt becomes `uncertain` with an `error_note`, never deleted) and are never auto-retried. Prompt routing: the policy of an in-flight prompt is immutable (`prompt_route_locked`); host loss cancels every pending prompt with a plumbed reason, never a synthesized answer; an inline `await ctx.ui.confirm()` inside `session_start` deadlocks the bind — detach it; multi-session inbound responses need the `sessionId` envelope. The desktop mirror reflects host sessions read-only through `thread.create`/`thread.meta.update`/subscribeShell: a desktop-side user rename survives host updates, a host rename during mirror downtime becomes the new baseline on restart, and a `project.create` failure warns once and drops that session from mirroring for the run. Completions are opt-in (`thread_report {kind:"completion"}` or the CLI writes a durable `completion_arms` row; an unbound session never opens `gateway.sqlite`), picked up at `session_start` and `wake` edges, and written at `agent_settled` with the last `agent_end`'s outcome (`completed`/`failed`/`cancelled`) — see [`gateway/AGENTS.md`](gateway/AGENTS.md).

Error taxonomy (`errors.ts` `THREAD_ERROR_CODES`, 41 codes): `invalid_arguments`, `caller_context_missing`, `not_found`, `ambiguous_target`, `scope_denied`, `name_conflict`, `not_resumable`, `orphaned`, `foreign_live_owner`, `no_active_turn`, `turn_conflict`, `not_steerable`, `message_too_large`, `queue_full`, `cursor_invalid`, `cursor_stale`, `idempotency_conflict`, `idempotency_in_progress`, `idempotency_uncertain`, `approval_unavailable`, `approval_route_locked`, `partial_commit`, `unsupported`, `overloaded`, `transport_closed`, `host_unavailable`, `internal_error`, `model_not_found`, `model_ambiguous`, `thinking_level_unsupported`, `loop_detected` (the gateway's only loop guard left: a session sending to itself), `binding_conflict`, `binding_mismatch`, `binding_inactive`, `stale_revision`, `stale_token`, `already_answered`, `answer_in_progress`, and the relay remainder. Prompt-route codes (separate union, `prompt-routing.ts`): `prompt_route_locked`, `prompt_response_not_authorized`, `prompt_not_found`. Every failure carries `next_action` naming the recovery step; `threadToolFailure` keeps the code taxonomy-validated.

**Conventions:** every entry point returns its outcome as data, the error branch carrying a taxonomy code and a `next_action` naming the recovery. Family policy lives in exactly one `promptGuidelines` string; no policy prose in per-tool metadata. Bounded everything: read budgets, queue sizes, candidate lists, fuzzy caps; a truncated read hands back one payload plus an opaque cursor. Durable state is written atomically (temp file, fsync, rename, directory fsync) with 0700/0600 modes.

## Anti-patterns

- Don't throw for an expected failure anywhere in this family; construct it through `threadToolFailure` so the code stays taxonomy-validated. Don't claim exactly-once delivery, and don't add dedupe to the engine on the correlation id here; the receipt layer is the dedupe seam. Don't describe cwd-basename fuzzy matching as auto-accepting; at weight 0.70 it can never clear the 0.72 floor alone. Don't put negated-use sentences in any indexed metadata field, and don't repeat a keyword string across the family.
- Don't write a report from model output or lifecycle text: only an explicit `thread_report` call writes the outbox, and a completion only at `agent_settled`.
- Don't touch the gateway store from a lifecycle edge every session runs (`agent_end`, `agent_settled`) unless this runtime has work there, and never hold such an edge on a store call: the store's write lock is shared with other processes. Don't auto-cancel a relayed question the way the headless task client does; it stays pending until `thread_answer` resolves it through its own binding.
- Don't send into sessions from the mirror, and don't write desktop data back into the host.

The live thread RPC client is loaded on the first asynchronous thread/gateway operation via `#omo-thread-client-runtime` (`src/components/thread/live-surface.ts` in source, `extensions/omo-thread-client.js` in the plugin). The component still registers tools, the store and lifecycle handlers synchronously; the registrar captures the operator socket before loading. One runtime promise/client is shared per facade across concurrent operations. A failed load is not cached: it rejects as `host_unavailable:<socket>` (classified by the thread tools) and the next operation loads again. Build freshness, required installation artifacts and bundle purity include this sidecar.
