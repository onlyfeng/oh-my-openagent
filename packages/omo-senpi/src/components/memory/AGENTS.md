# memory component

**Generated:** 2026-11-18 / c2691818a9

Kibitzer is a read-only recall judge; its only act is a nudge. ONE resident in-process sidecar per bound main session (`kibitzer/`); durable trace `recall/sidecars/<encoded-session>/` — the child's session JSONL plus `wakes.ndjson`, one bounded redacted line per settled wake (`kibitzer/observe.ts`), pruned after seven idle days and never while its session is live; no per-run directories. The user-visible notice is titled with a single fixed "Kibitzer" (glyph ✦, accent tone; opener-era `opener` fields ignored), body "recalled memory: <hint>", delivery provenance in the record never on screen — distinct from `memory.nudge`, the every-N-turns write reminder (`nudge-wiring.ts`).

Letta-Code-style persistent agent memory for omo-senpi, backed by `@oh-my-opencode/memory-core` (harness-neutral; zero Senpi imports). Parity target: letta-code@a75f4d93e's local-capable matrix, executed per `.omo/plans/letta-memory-parity-port.md` with the research corpus at `.omo/ulw-research/20260809-224128/`.

- Memory read headlines: `read-classifier-wiring.ts` reads the live bound identity repos from the session map; files inside get kind `memory`, a POSIX repo-relative label, and a headline from the restored 100-entry `recall-openers.ts` pool (lexical + real paths; `.git` metadata and escaping symlinks excluded; one picker avoids immediate repeats; Senpi memoizes across redraws). `registerReadClassifier` is feature-detected — older hosts debug-skip, the classifier unregisters after the last bound session. Independent of the memorian nudge notice (fixed `Aha!` title).
- Attribution: the architecture is inspired by letta-code (Apache-2.0; an independent reimplementation from observable behavior, no source copied). The working-agreement ledger (#10780) is a concept-only design inspired by dinobot (PolyForm-NC; no code, tests, or prompt text used).

## Declared divergences from letta-code@a75f4d93e

Every row is intentional, weighed against the research corpus (claim-graph.md):

1. Local-capable matrix only — Letta Cloud rows are out (org repos, server identity/secrets, `.af` import/export, semantic endpoints, cloud metadata/accounting); the push-only git mirror (`/memory-repository`) is the cloud-free sync story.
2. No mods-in-memory — a `mods/` dir may exist but nothing in it is ever loaded or executed (trusted code in memory expands attack surface).
3. No reflection arena, no channels — the A/B arena experiment and Discord/Telegram `/reflection` routing have no omo analog.
4. Local search is text-only by design, matching letta's local backend (vector/hybrid degrade to FTS-lite locally); senpi sessions scanned via the JSONL provider with archived-sidecar/internal-session exclusions; `--include-hidden` overrides.
5. No mid-conversation `<memory_update>` one-shot — letta special-cases one model; omo recompiles per run for every model (per-run `before_agent_start` re-check of HEAD).
6. No `/reflect --auto` selector subagent, no external-transcript staging, no `letta dream --to` doc maintenance; manual reflection takes `--recent N` / `--conversation <ids>` / free-text focus; the dream pass is an omo extension riding the reservation machine.
7. Recall is a resident judge, not letta's conversation-bootstrap injection — no bootstrap-time or lexical auto-injection; one resident read-only Kibitzer sidecar per bound session, woken at a prompt or `tool_call` hook (never at settle) only for un-judged lexical candidates, answering only through `nudge`; validated nudges land at the next tool boundary of the SAME turn or on the NEXT prompt; an idle session is never woken for a nudge alone; `/search` stays the manual surface (C46).
8. No onboarding tutorial personality / welcome hints — default seeds (`system/persona.md`, `system/human.md`) are the only first-run content.
9. Reflection sandbox default `auto`, not letta's fail-closed `required` (C33) — default-on reflection must not break hosts without seatbelt/bwrap; `"required"` restores letta semantics.
10. `memory_description`/`limit` frontmatter tolerance matches letta; block-scalar descriptions are rejected (letta's `>` cut-prefix acceptance treated as a bug); typed `kind` + `aliases` for people cards is an omo extension.
11. `str_replace` replaces the FIRST occurrence (C21); the exactly-one-match proposal was rejected for parity.
12. Message store = senpi session JSONL (letta's LocalStore JSONL not ported).
13. `reflection.trigger.step_count` stays at 25 (schema default); memory v2 changed the trigger machinery and added the dream kind, not the cadence.

## Extensions beyond parity

Active learning ON by default (`memory.enabled: true` + sub-features defaulting on); omo-only additions, not parity claims:

- Save nudge (`memory.nudge`): after `every_user_turns` (default 10) accepted user turns without a memory write, a nudge line joins the compiled metadata block; write detection keys on commit trailers (`Omo-Writer`/`Omo-Session`/`Omo-Turn`), never git author identity.
- Facts extractor (`memory.facts`): settle-time queue entries debounce (`debounce_settles`, default 4) into an in-process child using the shared memory-child helper and `record_fact`; `extraction.jsonl` run artifact; the parent applies the batch as one commit (`Generated-By: facts-extractor`); shutdown leaves queued entries for the next session_start reconcile.
- Oversized facts entry (#8984): ordinary batches stay under memory-core's 128 KiB `MAX_FACTS_PAYLOAD_BYTES`; a single entry above it runs WHOLE (never split or truncated) when ≤ 512 KiB (`FACTS_OVERSIZED_BYTES`) and the pinned model's known `contextWindow` fits — at most 8 provider requests, 4 096 output tokens each, `retry.maxRetries: 0`, no fallback rungs, auto-compaction off, ≤ 128 KiB / 256 accepted records; compaction, `resume_context_reduced`, a `length` stop, a model swap or any budget overflow fails the whole run with the queue and watermarks kept; entries above 512 KiB or unknown/too-small capacity are parked.
- Dream pass (`memory.dream`): distinct reservation trigger kind `"dream"` (`origin: manual|idle|shutdown|pressure`) running consolidation + skill-audit + people persona through the same worker pipeline; idle/shutdown use the conversation auto-selector; pressure compacts without a transcript-volume floor.
- People cards (`memory.people`): typed card + observation formats in memory-core (kind/aliases frontmatter, per-card `max_entries`/`max_entry_chars`), plus a relationship graph view in the palace.
- Soul v2 (`memory.soul`): `system/identity.md` joins `<self>` alongside the persona; committed soul edits surface a visible non-model-facing notice when `edit_notice` is true.
- Run supervisor: every reflection/dream child spawns through `memory-run-supervisor.mjs` (run identity handshake, `outcome.json` sentinel); on win32 process groups and POSIX signals are unavailable — the child spawns non-detached, graceful `child.kill()` fires at the SIGTERM instant and `taskkill /pid <pid> /T /F` at the SIGKILL instant, process-start identity is always null so an abruptly dead supervisor reconciles through the non-destructive UNKNOWN path to `abandoned.json`, and the bootstrap self-enforces the same absolute deadline. Facts do not use this supervisor.

## Deliberate constants (not knobs)

- Facts extractor category is pinned `"quick"` (literals in `facts-model.ts`; the `QUICK_CATEGORY` constant is the people-ask command's, not the facts runner's); resolution failure logs a warning and skips, never falls back to another category (schema comment in `omo-config-core/src/schema/memory.ts` records the same decision).
- Shutdown drain budget is 1500 ms (`SESSION_SHUTDOWN_DRAIN_BUDGET_MS`), under senpi's `sessionShutdownHandlerWarnMs`/`TimeoutMs`/`QuitBudgetMs` defaults (2 s / 10 s / 2 s, each settable and 0-disableable); `shutdown-drain.test.ts` reads the installed senpi defaults so a lowered host default fails the test instead of stranding the claim.
- Automatic reflection failures back off 5 s doubling to 5 min (non-manual, non-dream outcomes other than `merged`/`no_changes`); manual `/reflect` bypasses the window; success resets `consecutive_failures`/`next_eligible_at`.
- Automatic reflection parks after 3 consecutive non-retryable or 6 retryable failures and probes every 6 h while parked (classification in `worker/failure-policy.ts`; state in `runtime/reflection/park.json` under the scheduler lock); manual `/reflect` and `/dream` bypass; any merged/no_changes clears; the park edge is announced once per session, the footer shows ` paused`, `/doctor` reflection-health names it.
- Kibitzer pacing: 90 s wake deadline, reseed at 60% of `sidecar_max_tokens`, accepted-nudge cooldown 2 wakes per 10 min per session, child backoff 1 s doubling to 5 min — the configurable knobs are `category`, `max_items`, `event_caps`, `sidecar_max_tokens`, `max_concurrent_wakes`, `tool_budget`, `query_expansion` only. Pending reflection captures are bounded to 32 conversations / 4 MiB (whole-conversation first-seen eviction, evicted cursors retryable, byte budget counts UTF-8 JSON + nesting whitespace; a single oversized capture is evicted too).
