# memory worker

Detached `senpi -p` reflection/dream/facts child execution and the durable run lifecycle for the memory component: supervision, finalization claims, crash reconciliation, model resolution, health, and completion delivery. Children never touch git; the parent applies writes. Distinct domain; score 14: 147 files (incl. 16 `__fixtures__` child-process drivers), own barrel, `writeRunJsonAtomic` imported from ~20 files.

| `run-finalization*.ts` / `run-terminal-*.ts` | Terminal-state machine: finalization claim (`-claim.ts`), gate/settlement (`-settlement.ts`), git decision (`-git.ts`), types. `run-terminal-claim.ts` writes durable exclusive claims (wx candidate, fsync, hard-link, dir sync; stale-claim recovery rechecks raw contents under an infinite-wait lock); `run-terminal-gate.ts` / `run-terminal-precedence.ts` arbitrate published-outcome vs process-liveness races. Matching published outcomes win races; abandoned runs are never published; inactive runs must not complete. `cleanupAndRecord` runs after the decision is durable: a worktree or branch it cannot remove records `cleanupIncomplete: true` on the ledger instead of throwing, so a landed reflection still settles. |
| `run-reconciliation.ts` | Startup scan: run directories, process liveness, sentinel waiting, state repair. Retired directories with ledger/terminal timestamps older than the active reservation do not hide a confirmed-dead launcher; historical artifacts stay intact while pending work promotes. Terminal timestamps come from `final.json.finishedAt` or `abandoned.json.abandonedAt`. A run that already has `final.json` or `abandoned.json` is never quarantined: under a dead launcher its reservation is released as `failed` and the dir is untouched (its timestamps cannot attribute that terminal artifact to this reservation, so its outcome is not trusted). Unfinished runs are quarantined (`run-reconciliation-prelaunch.ts`: `quarantined.json` + `reservation.quarantined.json`, a `quarantined` receipt, reservation released, evidence untouched) only under a launcher proven dead on this host: an unreadable ledger (also requiring its recorded supervisor and child dead or absent), a run dir past the launch window with no prelaunch file, or an unrecoverable terminal claim. A launch interrupted before its ledger keeps its run dir and gets a pre-ledger `abandoned.json` (`launch_interrupted`) before release. A dead supervisor's child tip is recovered (`recoverUnpublishedWorktreeTip`, `recovered` then `merged`) only when the bootstrap's `child-exit.json` records this run id and attempt exiting 0, unsignalled, not timed out, between `ledger.startedAt` and the hard deadline; anything else fails closed. A retired-generation dir is skipped by the run-dir loop for the rest of the pass so it never settles the live reservation sharing its id. |
| `run-ghost-active.ts` | Classifies the two wedge shapes the retired-generation rule cannot see: a reservation without launcher identity (legacy record; probed for liveness when a pid survives, reclaimed outright otherwise) and a ledger older than the reservation with no terminal artifact. Classification only; the reclaim is the shared complete-as-failed + promote path and touches no artifacts. |
| `run-temporaries.ts` | Startup cleanup of run/completion JSON temporaries older than 24 hours, including terminal directories. Only complete `.json.tmp-<uuid>` or `.json.tmp-<pid>-<uuid>` suffixes match; durable `.json` records remain intact even when their run ids contain `.json.tmp-`. The PID comes from that same suffix and requires confirmed owner death; fresh files, directories, and live/unknown owners are preserved. |
| `run-reconciliation-sweep.ts` | Orphan sweep at the end of a reconciliation pass: reservation active/pending ids plus every non-terminal run dir are live, and `sweepReflectionOrphans` discards registered worktrees, stray `<epoch>-<runId>` dirs, and `memory/reflection-*` / legacy `reflection/run-*` branches older than the 15-minute grace. Deferred passes never sweep; failures warn through the injected logger and never fail the pass. |
| `run-liveness.ts` / `run-sentinel.ts` | Liveness probes and sentinel waits; the sentinel basename never fires on the relevant watcher path, so waiting degrades to a bounded timeout. |
| `resolve-model.ts` / `model-miss.ts` / `model-preflight.ts` / `model-cost.ts` / `fork-cost.ts` / `registry-fallback.ts` | Model ladder: ordered candidates with cost-aware routing (`chooseMemoryLaunchRoute`: 0.8 context-window fit ceiling, cached parent-prefix reads charged on every fork turn, facts surface excluded from fork routing), session/thinking inheritance, preflight caching (2 min, keyed by launcher + config-source mtimes + catalog mode; extension discovery is a separate child mode), retry classification (`classifyRetryableModelMiss`). `resolveReflectionModel` is shared by the reflection runner, facts runner, Kibitzer sidecar model, and the people-ask command; registry fallback rejects non-chat ids, requires >=131,072 context tokens when known, ranks by input cost, caps at 3. |
| `completion*.ts` | Durable completion records (`runtime/reflection/completions/`): record, deliver, render; `REFLECTION_*_ENTRY_TYPE` constants and renderer registration. |
| `health.ts` / `health-alert.ts` | READ-ONLY derived health over completion records (failure streak, fingerprint, last outcome; `senpi-memory.health` entries). ## Conventions

- Durable state transitions are separated from side effects: claim -> gate -> settle -> reconcile, each behind injectable seams (`now`, process checks, writer locks, reservation ports, subprocess runners).
- Atomic writes everywhere (temp + rename, 0600); tests use `tmpdir()` fixtures with explicit cleanup, real subprocess/filesystem/git seams, and `setDefaultTimeout` for integration cases.
- Races, crash windows, and terminal precedence are pinned by dedicated tests (`run-finalization-race`, `run-finalization-crash`, `run-terminal-precedence*`, `run-reconciliation-handoff`).

## Anti-patterns

- `health.ts` must never write - no transcript entries, no notifications, no nagging from a frozen burst.
- Never hide a pre-spawn resolution cause behind `child-stderr.log`; no child ran in that path.
- Never publish failed-child output into the memory repository; keep the cursor retryable.
- Abandoned runs must never be published; matching published outcomes win races.
- Non-retryable model failures must not consume the model chain. Provider names are assumed `/`-free; model ids may contain `/` (`model-preflight.ts`).
- Never infer termination from stdio `close` alone: descendants retain inherited pipes and `/proc` presence is not liveness while zombies remain - use the zombie-aware identity/liveness checks.
- Never treat a parseable but incomplete model catalog as proof that all candidates are unusable; keep the permissive reactive retry path.
